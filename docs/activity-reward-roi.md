# 领奖按钮 ROI 自动制备

领奖按钮不再使用手选范围 `[1000,120,190,100]`。没有缓存时，先用游戏数据中的任务描述确认任务页，再在整个 1280×720 画面中识别“一键领取／键领取”。Core 回调给出识别到的文字框，程序据此生成 ROI，不需要人工截图或另一套 OCR。

## 识别、复用与回退

完整路径为：

1. 每次先执行 MissionReady，确认任务页；缓存不会替代这个检查。
2. 有缓存时先尝试 CachedControls，没有命中就继续全屏 MissionControls。
3. 控件被识别后，在相应范围重新识别并点击。若缓存内的按钮在识别与点击之间移走，仍可回退全屏查找。
4. 页面已确认但全屏也没有按钮时，正常返回 nothing_to_claim。不写空 ROI，不删除以前的有效 ROI，也不认为奖励已全部领完。

只有已确认任务页后的控件／点击回调，且文字为上述候选、识别框在画面内，才可提供 ROI。取 Core 实际选中的框，左右扩展 `max(8,width/4)`、上下扩展 `max(8,height/2)`，使用整数像素并裁到画面边界。缓存命中和全屏发现均可刷新它；业务领取是否成功独立判断，仍需点击与领取回执。

## 当前资源缓存

缓存位于 `cache_directory/activity-roi/<key>.json`。key 包含活动实例及窗口、素材来源、导航版本、1280×720 坐标基准和制备算法版本；资源或活动改变时，不会复用旧范围。

日程结果回到 daemon 后，将有效 ROI 原子写入缓存；plan 与下一次日程准备读取它，再冻结进私有任务。已接纳的计划保持原快照，不在执行中修改共享 Core 任务表。缓存缺失、损坏、范围越界或当前未命中均不阻止全屏识别；写入失败只记录 `activity_reward_roi_cache_error`，不把已完成的领取改成失败。

文件只保存当前 ROI、身份与版本，不保存领取历史；领取结果与证据继续进入结构化日志，不新增 SQLite 历史表。按钮缺席和后续任务失败都不会把识别资源当作业务状态清空。

`activity_reward` 标记及结果中的 `claim_roi_key` 关联当前资源身份；回调发现有效区域时，结果另外携带 `claim_roi`。没有发现按钮时不生成该字段。
