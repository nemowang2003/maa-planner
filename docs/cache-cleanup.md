# 缓存自动清理

原生 Windows daemon 在启动一分钟后首次检查，此后每 24 小时检查一次。存在准备、执行、API 操作或其他维护时延后一分钟；新工作使用现有维护互斥，不与清理并行。停止或重启会等待正在执行的清理结束。

```toml
[cleanup]
enabled = true
apk_days = 1
download_days = 3
cache_days = 3
core_keep = 2
```

省略时使用上述默认值。enabled=false 禁用自动清理；天数接受 1–3650 的整数，core_keep 接受 1–100。修改配置沿用完整配置替换及文件监听流程，不新增清理 API。

| 数据 | 保留规则 |
| --- | --- |
| APK 完整包与遗留下载片段 | 最近成功使用后 apk_days 天（默认 1 天） |
| Core 下载归档、素材导出器下载归档 | 最近成功使用后 download_days 天 |
| 热更新快照、游戏表、作业响应、素材 bundle／索引／导出器、导出中间缓存及素材处理工作目录 | 最近成功使用后 cache_days 天 |
| daemon 管理的 Core 安装 | 每个平台与架构保留版本号最新的 core_keep 版；被执行任务使用或被锁定的旧版仍保留 |
| 已发布私有素材快照、公告来源证据、领奖 ROI、历史日志与状态库 | 不自动删除 |
| Core 单次执行目录、恢复现场、未知命名或布局的文件／目录 | 不自动删除 |

成功复用缓存会刷新其使用时间，不依赖 Windows 默认可能关闭的文件访问时间更新。目录按自身和内部文件中最新的修改／使用时间计算；不删除单个快照中的部分文件。

仍有冻结或未知执行记录时跳过整轮清理；恢复文件显示未结束或无法解析时也跳过。清理不自动恢复任务或终止进程。只处理程序明确生成的目录和内容寻址命名，遇到符号链接、junction 或内部重定向就保留，不沿链接清理外部目录。配置、认证目录和状态目录始终受保护。

每轮结果记录为 cache_cleanup 事件，提供 removed_entries、freed_bytes、busy_entries 和 errors；有未完成恢复文件时记录 skipped=recovery_pending。文件被占用或权限不足只影响该项，保留文件并继续其余项，不使日常失败，也不删除固定锁文件。

素材处理 jobs 中的源包、导出输入／输出和导出日志属于可重建中间产物，按 3 天默认期限清理；已经发布到 snapshots 的产物保留。它们与游戏 worker 的恢复现场不同，后者不自动清理。

过期目录先在同一父目录原子重命名为程序自己的 .cleanup-<随机标识>，再删除。若 Windows 文件占用导致删除中断，后续读取会得到缓存未命中，避免复用半删目录；下一轮继续回收这种待删目录。重命名失败则原目录保持不变。
