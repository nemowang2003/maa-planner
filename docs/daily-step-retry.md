# 日常业务任务错误检测与恢复排期

## 业务任务与执行步骤

恢复单位是配置中的业务任务。每个配置任务使用固定配置版本内的位置标识；任务重名、动态插入活动奖励或本轮跳过剿灭，都不会改变其他业务任务的标识。项目自动生成的活动任务奖励另有按活动 ID 关联的业务标识。Core 的 task_id、任务链和 task_checkpoints 保留作诊断证据，不作为恢复执行位置。

普通“刷理智”业务包含可选自动通关 prefix、刷图主体和可选活动商店 suffix。prefix 收到明确 Core 错误时，不提交刷图主体，记录整个刷理智业务失败并继续其他独立任务；主体报错不执行商店；商店收到明确 Core 错误，也使所属刷理智业务失败，即使主体已完成。阶段不独立排期，不保存 prefix／主体／suffix 的恢复检查点。任务链完成不等于游戏业务成功：结果不明的商店不会被认作业务成功，也不凭未知证据主动创建自动重试。

通关进度只使用认证账本。每关 Copilot 取得明确成功证据后立即由 daemon 登记，下一次规划重新读取账本；任务中途失败、未知或未收到认证的关卡不登记。恢复不从旧执行报告或关卡数量拼接另一份通关进度。原有同关三次明确战败规则保留；三连败、活动未解锁、没有可用集合等业务停止不凭空变成 Core 错误重试，完整通关条件不满足时不刷普通理智。

## 失败与掉线

普通业务单点错误后，继续尝试本轮其余独立任务。已成功的公招、领奖等业务不重跑；失败任务整体重跑。例如基建执行一半掉线，恢复重新规划并完整执行基建，不恢复到某个房间或某次点击。

Core 6.22.0 的普通 OfflineConfirm／OfflineConfirmAfterBattle 节点执行 Stop，只结束当前 ProcessTask 并返回 true；PackageTask 仍可能继续子任务。官方 GUI 另行监听非 StartUp 的 ProcessTask SubTaskStart，并调用 AsstStop 停止整个队列。[任务定义](https://github.com/MaaAssistantArknights/MaaAssistantArknights/blob/v6.22.0/resource/tasks/tasks.json#L1044-L1067)、[PackageTask](https://github.com/MaaAssistantArknights/MaaAssistantArknights/blob/v6.22.0/src/MaaCore/Task/PackageTask.cpp)、[GUI 回调处理](https://github.com/MaaAssistantArknights/MaaAssistantArknights/blob/v6.22.0/src/MaaWpfGui/Main/AsstProxy.cs)。

项目沿用这个判据，仅接受本 worker 注册任务的掉线节点起始回调，排除 StartUp；命中后记录 session_failure.kind=game_disconnected、节点、task_id、回调证据和时间，执行线程停止 Core。自动通关或商店内部掉线同样归属整个刷理智业务。StartUp 中的同名节点继续由 Core 有限点击重连，不视为新的中途掉线。

StartUp 失败、底层连接或增强截图失效等无法继续的情况停止本轮；取消及需要人工清理的结果不自动重放。项目不额外截图轮询登录弹窗；当前候选未识别到掉线节点时，仍沿用 Core 识别与错误路径。

子任务错误与业务失败分别记录。普通 SubTaskError 会增加 task_results.subtask_errors，单凭计数不触发恢复；若所属任务链最终 completed，且没有明确掉线或其他业务失败证据，该业务仍按 completed 结束。

## 排期、重新规划与边界

本轮剩余可执行任务尝试及 worker 清理结束后，依次延后 5／10／15 分钟，最多三次。掉线停止本轮后，清理完成才计时。scheduled_retries 只保存待重跑的业务标识、配置版本、原日程窗口、失败证据和互斥身份，不保存可重放的 Core 请求、附件或内部阶段进度。等待中的排期跨重启保留；准备或执行中的恢复被中断后标记 recovery_required，不自动假设任务没有执行而再次播放。

到期后复用日常准备入口，重新取得公共活动快照、Skland 观测，重新判断基建、剿灭、选图、自动作业及商店。已成功的独立业务不再执行；仅重做失败和未执行任务，但共享准备仍可能重新采集账号级库存和观测。每次运行内仍固定私有任务、附件及资源快照，不在执行中改共享 GUI 资源。Skland 请求的新响应仍可能含较早 storeTs，继续遵守现有未知数据及时间戳规则，不添加任意年龄门槛。

活动按恢复时刻重新判断：已结束活动不继续通关或兑换，刷理智可以依据当前活动／芯片／后备规则重新选图。周期日常恢复不能越过原下一次执行时刻；配置版本改变、排期取消或过期即不执行旧周期安排。daily.run 临时日常以显式 expires_at 限制恢复启动，使用接纳时固定的配置和显式附件，之后当前配置变化或无效不自动取消；库存、活动和自动作业仍重新观测、规划。周期恢复则重新读取当前基建文件。商店首次导航失败的停用及已完成兑换事实仍由领域状态决定，不因业务重试重置；重新规划遇到 disabled 时跳过商店。

会话首尾由 daemon 根据日程 session 编排；tasks 只接受业务任务，StartUp／CloseDown 通过 session 声明。每次恢复先执行 StartUp，再执行待恢复业务，最后执行已配置的 CloseDown。会话使用 lifecycle 标识，不把成功的首尾写入待恢复业务列表；收尾单独失败只重试会话，不重放成功业务。内部 resume_game_session 标记允许接续上轮留下的前台游戏；新普通请求仍检查外部占用，实例互斥、GUI 进程、Core 版本和增强截图等准入保护保留。重新规划失败不播放旧快照，按剩余重试次数继续退避。首次共享准备或 Skland 准备整体失败保留原告警和失败边界；自动通关准备失败且其他日常可继续时，刷理智业务明确记录失败而不是当作已完成。

用药／源石参数按每次执行尝试生效，重新执行刷理智业务会重新获得配置额度；不跨尝试累计预算。检查点粒度是完整业务任务，不能承诺任务部分动作的事务回滚或恰好一次。execution.run／copilot.run 及其批次成员不自动进入日常恢复排期；daily.run 是临时日常，复用上述业务恢复，operation 覆盖全部尝试。

普通刷理智的门禁只检查本次规划时已开放的区域／关卡；未来开放区域不阻塞，下一次规划按当时开放时间重新判断。商店仍要求全活动所有区域开放并完整认证。

账号 task_retry 告警及 status.scheduled_retries 提供待恢复业务、次数、下次时间和错误证据；成功后解除告警；达到三次恢复上限时仅保留当前失败告警，移除恢复排期，不再生成第四次 due_at。终结的日程、attempt、操作和恢复记录先写入结构化日志，再退出 SQLite。旧格式只保存冻结请求、缺少业务标识的等待排期标为 recovery_required，不猜测重放；新日程使用新格式。
